# پرامپت کامل ساخت پنل PXPanel (نسخه اولیه سالم و قابل اجرا)

> این پرامپت را دقیقاً همین‌طور به ایجنت کدنویسی بده. هدف: ساخت یک پنل مدیریت VLESS فارسی، تکی‌فایل‌محور، آماده دیپلوی روی Railway، که نسخه اولش بدون نقص کار کند.

---

## ۱. هدف پروژه

ساخت «PXPanel» — دروازه (Gateway) سریع و مدرن برای تونل‌زنی **VLESS** با داشبورد مدیریتی فارسی (راست‌به‌چپ)، دقیقاً با این قابلیت‌ها:

- تونل VLESS روی سه ترابرد قابل‌انتخاب: `vless-ws` (WebSocket)، `xhttp-packet-up`، `xhttp-stream-up`
- HTTP Proxy داخلی
- داشبورد مدیریتی کامل: آمار، نمودار ترافیک ساعتی، اتصالات زنده، لاگ فعالیت‌ها و خطاها
- لینک‌های نامحدود، هر کدام با محدودیت اختصاصی: حجم (KB/MB/GB)، سرعت (Mbps)، تعداد IP هم‌زمان، انقضا (روز)، فعال/غیرفعال لحظه‌ای
- Fingerprint (uTLS) و ALPN دستی برای هر کانفیگ + پورت اتصال دستی (نه فقط 443)
- خروجی QR Code برای هر لینک و هر ساب
- گروه‌های ساب: چند کانفیگ در یک گروه، یک لینک ساب عمومی (با امکان رمزدار کردن)
- ذخیره‌سازی وضعیت روی دیسک (نه فقط RAM) تا با ری‌استارت سرویس از بین نرود

## ۲. استک فنی (دقیقاً همین‌ها، بدون جایگزین)

```
fastapi==0.104.1
uvicorn[standard]==0.24.0
httpx==0.25.1
websockets==12.0
aiofiles>=23.2.1
httpx[http2]
```

- زبان: Python، فریم‌ورک: FastAPI، اجرا با `uvicorn.run("main:app", host="0.0.0.0", port=PORT)` در بلوک `if __name__ == "__main__":` ته فایل `main.py` (تا Railway بدون Procfile اجرا شود).
- بدون دیتابیس خارجی؛ کل وضعیت در یک فایل JSON روی دیسک.

## ۳. ساختار فایل‌ها (دقیقاً همین چیدمان)

```
main.py            # اپ FastAPI، احراز هویت، API لینک‌ها/ساب‌ها/آمار، استارت‌آپ
pages.py           # تمپلیت‌های HTML: LOGIN_HTML, DASHBOARD_HTML, get_public_page_html()
relay_vless.py     # رله VLESS روی WebSocket (پارس هدر VLESS + فوروارد TCP +统计)
xhttp_siz10.py     # پیاده‌سازی ترابردهای XHTTP (packet-up و stream-up)
speed_limit.py     # تابع throttle برای محدودیت سرعت هر کانفیگ
telegram_bot.py    # ربات تلگرام (polling با httpx) — فقط وقتی TELEGRAM_BOT_TOKEN ست است بالا می‌آید
requirements.txt   # وابستگی‌های بخش ۲
news.json          # فید خبر/اطلاعیه داخل پنل
```

## ۴. متغیرهای محیطی (دقیقاً همین نام‌ها و پیش‌فرض‌ها)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | `8000` | پورت اجرا (روی Railway خودکار ست می‌شود) |
| `DATA_DIR` | `./data` (یا `RAILWAY_VOLUME_MOUNT_PATH` اگر ست بود) | مسیر دیسک دائمی |
| `ADMIN_PASSWORD` | `pxpanel2026` | رمز ادمین (فقط به‌صورت هش ذخیره شود، هرگز plaintext) |
| `SECRET_KEY` | خودکار ساخته و در فایل `pixonpanel_secret.key` ذخیره شود | امضای سشن/کوکی |
| `RAILWAY_PUBLIC_DOMAIN` | `localhost` | دامنه عمومی برای ساخت لینک‌ها |
| `TELEGRAM_BOT_TOKEN` | خالی = ربات خاموش | توکن ربات (اختیاری) |
| `TELEGRAM_ADMIN_IDS` | خالی | آیدی عددی ادمین‌ها با کاما جدا شود |

- فایل وضعیت: `pixonpanel_state.json` داخل `DATA_DIR`؛ بعد از هر تغییر (ساخت/ویرایش/حذف لینک، مصرف ترافیک) ذخیره شود (debounce کوتاه مجاز است ولی از دست رفتن داده ممنوع).
- منطقه زمانی گزارش‌ها: `Asia/Tehran`.

## ۵. احراز هویت داشبورد

- صفحه `/login` (فرم رمز عبور) + API های `POST /api/login` و `POST /login`، خروج با `GET /logout` و `POST /api/logout`، وضعیت با `GET /api/me`، تغییر رمز با `POST /api/change-password`.
- سشن با کوکی امضاشده توسط `SECRET_KEY`. تمام API های `/api/*` (به‌جز لاگین و ساب‌های عمومی) بدون سشن معتبر `401` بدهند.

## ۶. موتور VLESS (قلب پنل — باید باینری-دقیق باشد)

- برای هر لینک یک UUID نسخه ۴ بساز.
- اندپوینت WebSocket برای هر ترابرد (مسیرها یکتا و غیرقابل‌حدس باشند).
- `relay_vless.py`: پارس باینری هدر VLESS (UUID شانزده‌بایتی، addon، command، پورت دو‌بایتی big-endian، سه نوع آدرس IPv4/Domain/IPv6)، اعتبارسنجی UUID در برابر جدول `LINKS`، سپس رله دوبلکس TCP با بافر ۲۵۶KB.
- IP واقعی کلاینت از `x-forwarded-for` (اولین مقدار) وگرنه `x-real-ip` وگرنه IP سوکت — در جدول اتصالات زنده ثبت شود (مهم چون پشت Railway هستیم).
- قبل از هر اتصال این سه چک: لینک فعال است؟ منقضی نشده؟ سقف IP هم‌زمان رد نشده؟ (`is_link_allowed` / `is_ip_allowed`).
- شمارش دقیق بایت ورودی/خروجی هر لینک → کم شدن از سهمیه حجم + ثبت در `hourly_traffic` + ثبت رویداد در `log_activity` و خطاها در `error_logs`.
- `speed_limit.py`: تابع `throttle` که سرعت هر اتصال را به سقف Mbps لینک محدود کند (۰ = نامحدود).
- لینک خروجی VLESS استاندارد بساز با پارامترهای: `security=tls&encryption=none&type=ws&host=&path=&sni=` + مقادیر `fp` (uTLS) و `alpn` و `port` دستی هر کانفیگ. لینک باید در v2rayNG/NekoBox/Streisand بدون دست‌کاری وصل شود.

## ۷. API های مدیریتی (همه با سشن ادمین)

- `POST /api/links` ساخت لینک (پارامترها: transport، حجم + واحد KB/MB/GB، سرعت Mbps، سقف IP، روزهای انقضا، fp، alpn، پورت) — پاسخ شامل UUID و لینک آماده و QR.
- `POST /api/links/auto` ساخت سریع با پیش‌فرض.
- `GET /api/links` لیست + `GET /api/links/{uid}/info` جزئیات و مصرف.
- ویرایش/حذف/فعال-غیرفعال لحظه‌ای لینک (از همان مسیرها با متد مناسب).
- `GET /api/protocols` لیست ترابردهای پشتیبانی‌شده.
- ساب‌ها: `POST /api/subs` ساخت گروه ساب (نام + لیست لینک‌ها + رمز اختیاری)، `GET /api/subs` لیست، `POST /api/subs/{sub_id}/links` افزودن لینک به گروه.
- `POST /api/mix-sub` ساخت ساب ترکیبی + `GET /api/categories` و `POST /api/categories`.
- آمار: `GET /stats` (صفحه)، `GET /api/activity` (لاگ)، `GET /api/connections` (زنده‌ها)، `GET /health` (سلامتی برای Railway).
- ساب عمومی (بدون لاگین): `GET /sub/{uuid}` و `GET /sub-all` (متن/ base64 مناسب کلاینت‌ها)، `GET /sub-group/{uuid_key}`، `GET /api/public/sub/{uuid_key}` — اگر گروه رمز دارد، بدون رمز `403` بده.

## ۸. رابط کاربری (pages.py)

- کاملاً فارسی و راست‌به‌چپ، تم تیره آبی/سرمه‌ای، فونت `Vazirmatn` از Google Fonts، آیکون `tabler-icons` از jsDelivr، لوگو به‌صورت base64 داخلی (بدون هاست خارجی).
- سه خروجی: `LOGIN_HTML` (فرم ورود شیک + نمایش راهنمای رمز)، `DASHBOARD_HTML` (تک‌صفحه: آمار، نمودار ساعتی، جدول لینک‌ها با ساخت/ویرایش/حذف/QR/کپی، مدیریت ساب‌ها، لاگ‌ها)، `get_public_page_html()` (صفحه ساب عمومی زیبا با دکمه کپی و QR).
- بعد از دیپلوی، داشبورد پیش‌فرض VLESS (بدون محدودیت) را در `/dashboard` نمایش بده تا کاربر فوراً کپی و وصل شود.
- لینک دانلود کلاینت‌ها (v2rayNG و...) داخل پنل باشد.

## ۹. ربات تلگرام (telegram_bot.py)

- polling با `httpx` به `https://api.telegram.org/botTOKEN` (بدون کتابخانه سنگین).
- فقط اگر `TELEGRAM_BOT_TOKEN` ست است در `startup` بالا بیاید، وگرنه فقط لاگ «ربات غیرفعاله» و ادامه کار پنل.
- امکانات v1: مشاهده لیست لینک‌ها (صفحه‌بندی ۶تایی)، ساخت لینک سریع، نمایش مصرف هر لینک — فقط برای `TELEGRAM_ADMIN_IDS`.

## ۱۰. دیپلوی روی Railway (بدون هیچ فایل اضافه)

- فقط همین ریپو (بدون Dockerfile/Procfile) باید با Python Nixpacks بالا بیاید.
- بعد از دیپلوی، کاربر یک Public Domain فعال می‌کند و مقدارش در `RAILWAY_PUBLIC_DOMAIN` می‌نشیند؛ همه لینک‌ها باید با همان دامنه ساخته شوند.
- Volume دائمی روی `DATA_DIR` وصل شود تا `pixonpanel_state.json` و فایل secret با ری‌دیپلوی نپرد.

## ۱۱. چک‌لیست قبولی نسخه اول (همه باید سبز شود، بدون استثنا)

1. `pip install -r requirements.txt` و `python main.py` بدون خطا بالا می‌آید؛ `/health` مقدار OK می‌دهد.
2. ورود با رمز پیش‌فرض به `/dashboard` کار می‌کند؛ تغییر رمز اعمال می‌شود.
3. لینک VLESS پیش‌فرض داشبورد در **v2rayNG واقعی** وصل می‌شود و اینترنت باز می‌کند (تست واقعی، نه فقط unit test).
4. ساخت لینک با سقف ۱۰۰MB → بعد از مصرف، اتصال جدید قطع می‌شود و در داشبورد «تمام‌شده» دیده می‌شود.
5. محدودیت سرعت (مثلاً 2Mbps) با تست سرعت واقعاً اعمال می‌شود.
6. سقف ۱ IP: اتصال دوم هم‌زمان با همان لینک از IP دیگر رد می‌شود.
7. انقضای ۱روزه و دکمه غیرفعال‌سازی بلافاصله اثر می‌کند.
8. صفحه `/sub/{uuid}` در کلاینت import می‌شود؛ ساب رمزدار بدون رمز `403` می‌دهد.
9. QR همه لینک‌ها اسکن و درست باز می‌شود.
10. بعد از kill و اجرای مجدد، همه لینک‌ها و مصرف‌ها از روی دیسک برمی‌گردند.
11. با `TELEGRAM_BOT_TOKEN` خالی، پنل کامل کار می‌کند و ربات فقط لاگ می‌دهد.

## ۱۲. قوانین کدنویسی

- کامنت‌ها فارسی و کوتاه؛ هیچ رمز/سکرتی در کد هاردکد نشود.
- هر جا تصمیم مبهم بود، امن‌ترین و ساده‌ترین رفتار سازگار با چک‌لیست بالا را انتخاب کن و در انتها لیستش کن.
- خروجی نهایی: کل فایل‌های بخش ۳ + گزارش تیک‌خورده چک‌لیست بخش ۱۱ با دستورات دقیقی که برای تست زدی.

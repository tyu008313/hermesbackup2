# پرامپت کامل ساخت «NEON PANEL» — نسل جدید، ریمیکس سطح‌بالا، بدون باگ

> این پرامپت را دقیقاً همین‌طور به ایجنت کدنویسی بده. هدف: یک پنل مدیریت VLESS فارسی کاملاً جدید با تم نئون، پایدارتر و تمیزتر از هر پنل موجود، که نسخه اولش واقعی کار کند — مخصوصاً روی IPهای کلادفلر.

---

## ۱. چشم‌انداز (ویژن)

ساخت «Neon Panel» — پنل فروش/مدیریت کانفیگ VLESS با هویت بصری **Neon تیره** (مشکی + نئون آبی/بنفش/سبز، glow، glassmorphism). سه ستون اصلی:

1. **کانفیگ‌هایی که واقعاً کار می‌کنند** — هیچ لینک مرده‌ای در پنل نمایش داده نشود.
2. **بخش IPهای تمیز کلادفلر** — قلب تپنده پنل (جزئیات در بخش ۷).
3. **صفر باگ در v1** — با چک‌لیست تست واقعی (بخش ۱۲)، نه فقط یونیت‌تست.

## ۲. استک فنی (ثابت، بدون جایگزین)

```
fastapi==0.104.1
uvicorn[standard]==0.24.0
httpx==0.25.1
websockets==12.0
aiofiles>=23.2.1
qrcode[pil]
httpx[http2]
```

- فقط Python + FastAPI. بدون دیتابیس خارجی؛ وضعیت در `neon_state.json` روی دیسک (atomic write: نوشتن در فایل موقت + rename).
- اجرا: `uvicorn.run("main:app", host="0.0.0.0", port=PORT)` در `if __name__ == "__main__":` تا روی Railway بدون Procfile/Dockerfile بالا بیاید (Nixpacks + requirements.txt کافی است).

## ۳. ساختار فایل‌ها


## ۴. متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | `8000` | پورت اجرا |
| `DATA_DIR` | `./data` (یا `RAILWAY_VOLUME_MOUNT_PATH`) | دیسک دائمی + Volume روی Railway |
| `ADMIN_PASSWORD` | `neon2026` | فقط هش ذخیره شود (bcrypt/sha256+salt)، هرگز plaintext |
| `SECRET_KEY` | خودکار + ذخیره در `neon_secret.key` | امضای کوکی سشن |
| `PUBLIC_DOMAIN` | `localhost` (روی Railway همان دامنه سرویس) | دامنه‌ای که در لینک‌ها گذاشته می‌شود |
| `TELEGRAM_BOT_TOKEN` | خالی = ربات خاموش | توکن ربات |
| `TELEGRAM_ADMIN_IDS` | خالی | آیدی ادمین‌ها با کاما |

- لاگین rate-limit داشته باشد (مثلاً ۵ تلاش неуда در ۵ دقیقه = بلاک موقت IP).
- منطقه زمانی همه گزارش‌ها: `Asia/Tehran`.

## ۵. موتور VLESS (باید باینری-دقیق و ضد-باگ باشد)

- UUID نسخه ۴ برای هر لینک؛ مسیرهای WebSocket/XHTTP یکتا و غیرقابل‌حدس.
- پارس کامل هدر VLESS: نسخه، UUID شانزده‌بایتی، addon، command (فقط TCP=1 قبول، UDP رد با خطای تمیز)، پورت big-endian، هر سه نوع آدرس (IPv4/Domain/IPv6) با اعتبارسنجی طول.
- هر بایت ورودی/خروجی با lock مناسب شمارش شود (race condition ممنوع — تست هم‌زمان ۵۰ اتصال).
- ترتیب چک‌ها قبل از اتصال: لینک فعال؟ منقضی؟ حجم مانده؟ سقف IP هم‌زمان؟ IP تمیز منتسب سالم است؟
- IP واقعی کلاینت از `x-forwarded-for` (اولین) وگرنه `x-real-ip` — چون پشت Railway/CDN هستیم.
- هر خطا (UUID اشتباه، تایم‌اوت upstream، قطع‌شدن) با timestamp و علت در `error_logs` ثبت شود؛ هیچ‌وقت exception خام به کلاینت نرسد.
- لینک خروجی استاندارد با `security=tls&encryption=none` + `fp` (uTLS: chrome/firefox/safari/random) + `alpn` + `port` دستی — باید در v2rayNG و NekoBox و Streisand بدون دست‌کاری import و connect شود.

## ۶. مدیریت لینک‌ها (هر لینک این فیلدها را دارد)

- نام، transport (`vless-ws` / `xhttp-packet-up` / `xhttp-stream-up`)، حجم (عدد + واحد KB/MB/GB، صفر = نامحدود)، سرعت (Mbps، صفر = نامحدود)، سقف IP هم‌زمان (صفر = نامحدود)، روزهای انقضا (خالی = دائمی)، fp، alpn، پورت، **IP تمیز منتسب** (بخش ۷)، وضعیت فعال/غیرفعال.
- API کامل: ساخت، ساخت سریع (auto)، لیست با مصرف لحظه‌ای، جزئیات، ویرایش، حذف، تاگل فعال‌سازی، تمدید (+روز / +حجم)، ریست مصرف.
- دکمه **«تست اتصال»** برای هر لینک: سرور خودش با همان پارامترها یک handshake واقعی تا upstream می‌زند و نتیجه (OK + پینگ ms / FAIL + علت) را نشان می‌دهد. لینکی که تستش FAIL است با بج قرمز «خراب» مشخص شود و از ساب‌های عمومی حذف شود تا هیچ‌وقت لینک مرده دست مشتری نرود.

## ۷. بخش IPهای تمیز کلادفلر (فیچر کلیدی — دقیق پیاده شود)

- جدول IPها: آدرس، پورت، میانگین پینگ، نرخ موفقیت، آخرین تست، وضعیت (سالم/مشکوک/مرده)، برچسب (مثلاً ایرانسل/همراه).
- افزودن تکی + ایمپورت دسته‌ای (هر خط یک IP، پشتیبانی از رنج CIDR مثل `104.16.0.0/12` با باز کردن خودکار).
- **تست خودکار**: برای هر IP یک کانکشن واقعی TCP+TLS handshake به پورت 443 با SNI دامنه پنل + یک درخواست سبک؛ ثبت پینگ و success/fail. تست دستی تکی و «تست همه» + زمان‌بندی خودکار (پیش‌فرض هر ۳۰ دقیقه، قابل تنظیم).
- **امتیازدهی**: اسکور = ترکیب پینگ پایین + آپتایم بالا؛ مرتب‌سازی خودکار بهترین‌ها بالا.
- **اتصال به کانفیگ**: هر لینک می‌تواند یک IP تمیز مشخص یا حالت `auto` (بهترین سالم) داشته باشد؛ لینک خروجی با `address = IP تمیز` و `sni/host = دامنه اصلی` ساخته شود تا روی اپراتورهای مختلف ایران کار کند.
- اگر IP منتسب لینکی مرد، `health.py` خودکار آن را با بهترین سالم جایگزین و در لاگ فعالیت ثبت کند (failover بدون دخالت دست).
- خروجی «ساب IP تمیز»: لیست آماده IPهای سالم برای کپی.

## ۸. ساب‌ها و اشتراک

- گروه ساب: نام + لیست لینک‌ها + رمز اختیاری + تاریخ انقضا + سقف مصرف گروهی (اختیاری).
- خروجی‌ها: `GET /sub/{uuid}` (متن چندخطی + نسخه base64 با `?b64=1`)، `GET /sub-group/{key}` صفحه عمومی زیبا با کپی تکی/همه + QR، بدون رمزِ درست = `403`.
- فقط لینک‌های سالم (تست OK) و فعال و منقضی‌نشده وارد ساب شوند — قانون طلایی.
- `POST /api/mix-sub`: ترکیب چند لینک در یک ساب آماده فروش.

## ۹. داشبورد نئون (pages.py)

- فارسی RTL، فونت Vazirmatn، آیکون Tabler، پس‌زمینه مشکی عمیق + گرید + orbهای نئونی + کارت‌های شیشه‌ای با glow. کاملاً ریسپانسیو (موبایل‌فرست — مشتری با گوشی می‌خرد).
- بخش‌ها: نوار آمار زنده (کاربران آنلاین، مصرف امروز، لینک سالم/خراب)، نمودار ترافیک ساعتی (canvas، بدون کتابخانه خارجی سنگین)، جدول لینک‌ها (ساخت/ویرایش/حذف/QR/کپی/تست اتصال/تمدید با یک کلیک)، مدیریت IPهای تمیز (جدول + تست + ایمپورت + اسکور)، مدیریت ساب‌ها، لاگ فعالیت و خطاها (با فیلتر)، خبرها از news.json.
- صفحه لاگین نئون جدا با پیام خطای فارسی تمیز.
- لینک دانلود کلاینت‌ها (v2rayNG/NekoBox/Streisand) داخل پنل.

## ۱۰. ربات تلگرام ادمین

- فقط با `TELEGRAM_BOT_TOKEN` بالا بیاید (polling با httpx، بدون کتابخانه اضافه).
- دستورات: `/links` لیست با مصرف (صفحه‌بندی)، `/new` ساخت سریع، `/test <id>` تست اتصال، `/ips` وضعیت IPهای تمیز، `/sub <group>` گرفتن لینک ساب — فقط برای `TELEGRAM_ADMIN_IDS`، بقیه فقط پیام «دسترسی نداری».

## ۱۱. قوانین ضد-باگ (الزامی، نه پیشنهادی)

- همه ورودی‌های API اعتبارسنجی شوند (حجم منفی، پورت نامعتبر، UUID بدفرم → `422` با پیام فارسی).
- ذخیره دیسک atomic + بعد از هر تغییر مهم؛ با kill -9 هم حداکثر چند ثانیه داده از دست برود.
- هیچ رمز/توکنی در کد، لاگ یا پاسخ API لو نرود.
- باگ‌های کلاسیک پنل‌های قبلی که **نباید** تکرار شود: شمارش ترافیک منفی/دوبار، گیر کردن IP در جدول اتصالات بعد از قطع (heartbeat + تایم‌اوت ۶۰ ثانیه و پاک‌سازی دوره‌ای)، نمایش لینک مرده به مشتری، پریدن وضعیت با ری‌استارت، لو رفتن مسیرهای داخلی در خطاها.

## ۱۲. چک‌لیست قبولی v1 (همه با تست واقعی، بدون استثنا)

1. نصب و اجرا تمیز؛ `/health` سالم.
2. ورود، تغییر رمز، rate-limit لاگین (۶ رمز اشتباه → بلاک موقت).
3. لینک پیش‌فرض در **v2rayNG واقعی** وصل و اینترنت باز می‌کند.
4. سقف حجم ۱۰۰MB واقعاً قطع می‌کند؛ تمدید دوباره وصل می‌کند.
5. throttling سرعت (مثلاً 2Mbps) با speedtest حس می‌شود.
6. سقف ۱ IP: دستگاه دوم رد می‌شود؛ بعد از قطع دستگاه اول و ۶۰ ثانیه، دستگاه دوم وصل می‌شود (تست پاک‌سازی اتصال).
7. انقضا و تاگل غیرفعال‌سازی بلافاصله اثر می‌کند.
8. ایمپورت ۵۰ IP تمیز + تست همه + اتصال یک لینک به IP تمیز و اتصال موفق کلاینت با همان لینک.
9. کشتن IP منتسب (شبیه‌سازی مردن) → failover خودکار به بهترین سالم + ثبت در لاگ.
10. ساب در کلاینت import می‌شود؛ لینک خراب داخل ساب نیست؛ ساب رمزدار بدون رمز 403.
11. kill -9 و اجرای مجدد → همه‌چیز از دیسک برمی‌گردد.
12. ۵۰ اتصال هم‌زمان به یک لینک → شمارش ترافیک دقیق و بدون کرش.
13. بدون توکن تلگرام، پنل کامل کار می‌کند.

## ۱۳. خروجی نهایی ایجنت

کل فایل‌های بخش ۳ + گزارش تیک‌خورده بخش ۱۲ با دستورات دقیقی که برای هر تست زده. اگر جایی مجبور به انتخاب شدی، امن‌ترین و ساده‌ترین گزینه سازگار با این چک‌لیست را بگیر و در انتها فهرستش کن.
